## Three concrete migration objectives

1. **YAML/JSON and file round trips with inheritance.** Preserve the behavior
   measured by test_basic.py::test_simple, test_nested_models, and
   test_io.py::test_file_io. Existing YamlModel/YamlModelMixin subclasses must
   parse their own YAML and JSON, preserve nested model data, and retain the
   expected JSONDecodeError when YAML is explicitly parsed as JSON. The mixin
   wraps Pydantic v1 parse_raw/parse_file and serialization internals; changing
   method names alone may not preserve those dispatch rules.
2. **Secret-field redaction.** Preserve
   test_secret_types.py::test_secret_types_no_rt: secret values are available
   through get_secret_value before dumping but must not reappear after YAML
   serialization and parsing. The existing test_secret_types_roundtrippable
   is already xfail because custom encoder support is absent. Keep that
   original status visible; do not turn it into evidence of implemented support.
3. **Versioned configuration validation.** Preserve both tests in
   test_versioned.py with semver installed: a valid version loads, too-low or
   too-high versions raise ValidationError, invalid min/max configuration
   raises ValueError, and parsed SemVer/data values match. This crosses a
   custom __get_validators__ type and v1-style model/config validation, so it
   tests semantic migration rather than textual decorator substitution.

Full-suite outcomes still determine acceptance; these three objectives explain
developer value and do not permit dropping other tests. The original
test_basic.py::test_readme has no assertions; retain it, disclose it and do
not present it as meaningful behavioral coverage. No test-count prediction
is made before collection.

## Native-v2 and original-outcome acceptance

- Candidate environment uses pydantic==2.12.5, held fixed for both comparator
  and BranchShift. Update only the Pydantic dependency requirement as the
  shared standard dependency step; retain pytest configuration and tests.
- Require preserved original testcase identities, no failures, and every
  baseline passed testcase still passed. Existing skipped/xfail cases may
  stay skipped or become passed. A newly skipped original pass is a failure.
- Record counts, xfail/skip reasons, warnings, pip check, changed lines and
  source/test fingerprints. Do not equate all collected tests with assertions.
- Native-v2 structural probe should be about this library: after migration,
  its exported YamlModel must be a subclass of the installed native
  pydantic.BaseModel and expose model_fields. Merely installing Pydantic 2
  while moving the entire library to pydantic.v1 is a compatibility result,
  not this native-v2 migration success. Existing YAML behavior tests remain
  the behavioral oracle; do not substitute a generic JSON-payload demo.
- Apply the selected exact patch to the clean baseline and repeat the same
  environment, behavior, outcome and native-v2 checks.
